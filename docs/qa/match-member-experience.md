## 成员流程

| 步骤 | 预期行为 |
| --- | --- |
| 单打报名 | 点击报名后显示成功状态和签位发布指引；退出报名可展开 |
| 团体加入 | 优先提供邀请码与公开队伍加入入口；创建队伍、成员和联系信息按需展开 |
| 加入完成 | 自动滚动并聚焦自己的队伍，显示成队状态和下一步 |
| 查看签位 | 已参赛成员默认看到自己的对局；完整赛程使用小组交叉对阵表和左右汇聚的淘汰签表 |
| 录入比分 | 填写双方局分或队伍总分，由比分推导胜方；未填完或不合法时不能提交 |
| 等待确认 | 显示符合现有规则的确认人；团体明确显示冻结队长的职责 |
| 对手确认 | 独立对手账号核对后确认；登记方原页面和弹窗自动更新为已确认 |
| 查看赛后成绩 | 默认保留“我的成绩”，只列自己参加过的场次 |

## 复测准备

使用仓库的本地 PostgreSQL 工作流和 `npm run seed:v2:acceptance` 生成虚拟账号及单打、双打、团体案例。种子脚本只接受回环地址上的专用数据库；临时账号信息写入 `.local-postgres/v2-acceptance-data.json`。不要提交账号文件、数据库文件或环境配置。

浏览器复测时至少使用成员、对手和管理员三个独立会话。分别检查报名、签位、合法与非法比分、确认、普通团体队员只读、赛后成绩，以及窄屏横向签表、键盘标签切换和对话框关闭。

## 规则边界

本次只调整页面呈现与反馈。提交仍使用原有 fixture ID、版本和结果修订 ID；服务端继续校验权限、冻结名单、局制和成绩状态。双打确认资格沿用当前任意非登记参赛成员规则，团体沿用冻结队长规则。

比分争议的默认负责人及联系入口尚待业务确认，当前保留联系比赛管理员的提示。关闭赛事后的补偿、积分和 ELO 结算规则不由本次界面改动改变。
