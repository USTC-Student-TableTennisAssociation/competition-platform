# 重构后的比赛规则

本文记录 2026-09-07 已确认的最终产品规则，优先于早期 V2 文档中的过渡期、冻结搭档和历史兼容约束。

## 发布与历史

- 正式比赛一次性切换到新实现。实际没有未结束的旧比赛；旧数据库中的进行中状态是历史错误，不以这些状态继续维持旧写入流程。
- 旧正式比赛精简归档，只保留比赛基本信息、已确认赛果和个人战绩。不恢复旧分组、签表或报名交互。
- 旧未确认申报不进入正式战绩，不自动确认、不新增结算，也不保留在线确认入口；原始记录由迁移前备份保留。
- 旧参赛证明下载和补领不是兼容要求。新比赛继续支持参赛证明。
- 用户已有积分、ELO、胜负汇总及历史流水保留，结构迁移不重算、不重复结算。
- 快速约球继续作为独立业务使用；共用表是否保留取决于实际引用，不能按旧文件名或表名批量删除。

## 赛制与名单

- 三种正式赛型使用一套比赛内核；组织者提前设置局制，录分者只按指定局制录入比分。
- 团体目前记录队伍总比分、按该场冻结名单整队结算。每场名单与结算策略可追溯，保留未来增加实际出场名单、按实际出场者结算的扩展边界，不反向重算旧比赛。
- 分组后只有平台管理员可以更换双打搭档或团体成员；保留组合/队伍的签位和赛事成绩。
- 换人必须记录原因和名单版本，只影响未开始的对局。已开始、已提交赛果、已完成对局保留原名单。
- 个人成绩、积分和 ELO 始终归属于当场名单。A+B 已完成一场后换为 A+C，C 不继承第一场的个人成绩。

## 中途退赛

- 支持已经开赛或已完成部分场次后的管理退赛。
- 已确认成绩及其结算保留。已打完但未确认的场次须先由管理员核实，不因为退赛而自动清空。
- 剩余场次按弃权处理；弃权计入本赛事排名和晋级，不增加个人 ELO、积分或胜负统计。
- 双方均无法参赛时不伪造获胜者；淘汰签表按原结构推进，不重新抽签。
- 普通管理退赛与违规取消资格记录不同原因；历史赛果撤销通过独立纠错流程处理。

## 页面交互

- 普通视图突出报名状态、我的对局、待确认成绩和最终成绩；管理操作集中呈现，三种赛型遵循相同的角色视图。
- 报名、名单、赛程和成绩的业务状态有明确来源，不向用户展示 Entry、快照、事务或引擎版本等实现术语。
- 退赛与换人展示影响范围及待处理场次；服务端在执行时重新检查权限、版本和比赛状态。

## 验收

创建与局制设置 → 报名/组队 → 分组发布 → 录分/确认 → 管理换人 → 中途退赛 → 晋级/完赛，覆盖单打、双打和团体。
同时验证历史页只读、未确认旧申报不进入战绩、已确认历史不重算，以及新成员不继承更换前的个人成绩。
